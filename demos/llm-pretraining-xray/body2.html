从网页快照到训练语料

模型吃什么，比模型长什么样更费人力。原料是公开网页的快照（Common Crawl 每一两个月发布一次，每次几十亿个网页）、代码仓库、书籍、论文和各种专门收集的数据；输出是一份去重、过滤、按比例混好的 token 序列。这一步占用的人力通常比模型结构多得多，而它的每一个子决定都有同一个难处：好数据的定义，只能用训出来的模型来检验。所以数据团队的标准动作是消融：固定一个小模型，比如 FineWeb 用的 1.71B 参数训 28B 到 350B token，只换数据处理的一个环节，比较下游任务的平均分。

抽取与基础过滤

Common Crawl 同时提供原始网页（WARC）和它自己抽好的纯文本（WET）。FineWeb 发现 WET 里留了太多导航栏和菜单，改用 trafilatura 从 WARC 重新抽取，同样的训练量下分数明显更高。之后是三道基础过滤：按网址黑名单去掉成人网站；用 fastText 的语种分类器只留英文，得分阈值 0.65；套用 MassiveText 的质量和重复度规则。对 96 个快照做完这三步，用 GPT-2 分词器计数，还剩约 36T token。【文中有据，FineWeb 第 3 至 4 页、图 2】

Llama 3 报告里有一个反常识的细节：他们发现以网页为主的模型训练在保留 Markdown 记号的文本上效果更差，于是把所有 Markdown 标记都删掉了。【文中有据，Llama 3 报告第 5 页】这说明抽取格式本身是一个超参数：同一段内容带不带格式符号，模型学到的分布不一样，而下游评测几乎全是纯文本。

去重的反直觉结果

网页里有大量重复：镜像站、模板页、转载。去重的标准工具是 MinHash：把每篇文档切成 5 个词一组的片段，用 112 个哈希函数各取一个最小值，得到一个 112 维的签名；再把签名分成 14 个桶，每桶 8 个值，只要有一个桶的 8 个值全部相同，两篇文档就算重复。这个分法对应一条 S 形的判定曲线。两篇文档相似度（Jaccard 系数）为 $s$ 时，单个桶全同的概率是 $s^8$，14 个桶里至少一个全同的概率是：

$$P(s)=1-(1-s^{8})^{14}$$

代几个数：$s=0.6$ 时 $P=0.21$，$s=0.75$ 时 $P=0.77$，$s=0.9$ 时 $P\approx1$。曲线的陡坡落在 0.75 附近，这就是 FineWeb 说的针对至少 75% 相似的文档。【文中有据，FineWeb 第 5 页；数值是本文按公式算的】增加每桶的哈希个数，陡坡右移、判得更严；增加桶数，陡坡左移、判得更松。112 个哈希的总预算固定时，这两个旋钮互相牵制。

直觉上去重越彻底越好。FineWeb 的第一版就是这样做的：从最新的快照往前，每个快照都和之前处理过的所有快照一起去重。做完只剩 4T token，最老的那些快照被删掉了九成。用这份数据训模型，结果和不去重几乎一样，远低于 RefinedWeb。

他们接着做了一个漂亮的对照。在 2013 年 48 周那个老快照里，被全局去重保留下来的 31B token 训一个模型；被删掉的约 460B token 只在快照内部去重后得到 171B，再训一个模型。结果被删掉的那部分训出来的模型更好。人工翻看之后发现，留下来的一成里广告、关键词堆砌和格式混乱的页面更多。【文中有据，FineWeb 第 5 至 6 页、图 3 和图 4】

道理在去重留下了什么。好页面会被转载、被镜像、跨快照反复出现，所以在全局去重里成片地被判为重复删掉，只剩一份；垃圾页面往往每次抓取都不一样，反而每份都是唯一的，全部留下。全局去重于是把垃圾在剩余数据里的比例放大了。改成每个快照内部单独去重，结果是 20T token，训出来的模型追平了 RefinedWeb。作者的假设是：去重的主要收益来自删掉那些在每个快照里都有成千上万份副本的巨大重复簇，而重复次数在一百以下的小簇，删掉反而有害。

图 4FineWeb 的数据流，条的长度正比于剩下的 token 数（GPT-2 分词器）。逐步往下看；第三步是被放弃的全局去重，用橙红标出。最后的 15T 是 FineWeb，1.3T 是再经过教育质量分类的 FineWeb-Edu。数字出自 FineWeb 论文第 4 至 9 页。

值得对照的是 Llama 3 的做法：他们恰恰做了全局的文档级 MinHash 去重，另外还做了网址级去重（同一网址只留最新的版本）和很激进的行级去重（在每 3000 万篇文档的桶里，出现超过 6 次的行全部删掉）。报告承认行级去重删掉的不只是导航栏和 cookie 提示，也有高频的好文本，但实验上效果明显更好。【文中有据，Llama 3 报告第 5 页】两家的结论不矛盾：Llama 3 在去重之后还有好几层基于模型的质量过滤，全局去重放大的那部分垃圾会在后面被筛掉；FineWeb 的全局去重实验发生在质量过滤之前。【推断，依据：两份报告的处理顺序】

质量分类器

启发式规则能删掉明显的垃圾，删不掉写得通顺但没有信息量的页面。这一层要靠分类器，而分类器的标注本身也越来越多地由大模型来做。

FineWeb-Edu 是一个公开得很完整的例子。他们让 Llama-3-70B-Instruct 给 46 万个网页的教育价值打 0 到 5 分，用的是逐条加分的提示词，并且特意要求按中小学的知识水平来评，避免模型偏爱 arXiv 摘要一类的高度专业文本。然后在 Snowflake-arctic-embed-m 嵌入模型上训一个线性回归头，用 41 万条标注训练、5 万条验证。阈值取 3 分时，验证集 F1 是 82%。把这个分类器跑遍 15T token 用了 6000 个 H100 卡时，最后留下 1.3T token。1.71B 模型训 350B token，MMLU 从 33% 到 37%，ARC 从 46% 到 57%。【文中有据，FineWeb 第 8 至 9 页】

代价写在同一段里：阈值 3 是在知识类任务和 HellaSwag 这类常识续写任务之间折中出来的。教育类过滤偏向教科书式的文本，会损失口语、叙事和网络上的日常知识。Llama 3 用了两种分类器：便宜的 fastText，判断一个网页会不会被维基百科引用；贵一些的 DistilRoberta，学 Llama 2 对网页质量的判断。代码和数学另有专门的分类器和抽取流程，因为它们的 token 分布和自然语言差得太远。【文中有据，Llama 3 报告第 5 页】

好文本不够用之后的改写

过滤越严，留下的好数据越少。FineWeb-Edu 从 15T 里只留下 1.3T；而 2025 年的旗舰模型要喂 15T 到 36T token。缺口只有两种补法：把好数据重复多看几遍，或者把好数据换个说法再写一遍。

Kimi K2 的报告把这两种办法放在一起比过。他们拿维基百科类的知识文本，在一个早期检查点上试了三种用法，用 SimpleQA（一个考事实问答的评测）打分：原文重复 10 遍是 23.76；改写一次、再把改写版重复 10 遍是 27.39；改写 10 次、每个版本只看一遍是 28.94。【文中有据，Kimi K2 报告第 5 页、表 1】同样的知识，用十种说法各读一遍，比同一种说法读十遍记得牢。这和人背书的经验一致：换着角度讲同一件事，比把同一页念十遍有用。

改写不是随便让模型复述。K2 的做法有三层：提示词要求换风格、换视角但忠实于原文；长文档切成段，逐段改写，每段都看得到前面已经改好的部分，保证全文连贯；改写完逐段和原文比对语义，偏离的丢掉。报告自己也保留了警惕：每份语料最多改写两次，并且承认合成数据在规模放大后会不会带来幻觉和毒性，还需要更多研究。【文中有据，Kimi K2 报告第 5 至 6 页】

这里的取舍和蒸馏一样：改写用的模型有自己的口头禅和偏好，它们会随着改写数据进入下一代模型的预训练。后面讲说人话的那一节会回到这件事。【推断】

配比、退火与给数据估价

各个来源清洗完之后，要决定按什么比例混。Llama 3 最终的配比是：通用知识约 50%，数学和推理 25%，代码 17%，多语言 8%。这个配比本身也是用小模型的缩放律实验选出来的：在一个候选配比上训几个小模型，预测大模型在这个配比上的表现，换一个配比重复，挑出候选后再训一个更大的模型验证。他们还训了一个知识类别分类器，把网页上过度代表的类别（比如艺术和娱乐）降采样。【文中有据，Llama 3 报告第 6 页】

配比不是一成不变的。Llama 3 在训练过程中改过几次：提高非英语数据的比例，提高数学数据的比例，在后期加入更新的网页数据把知识截止时间往后推，把事后发现质量较差的子集降采样。【文中有据，Llama 3 报告第 14 页】

新数据源层出不穷，不可能每来一份小数据集就做一套缩放律实验。Llama 3 用了一个便宜得多的办法：拿一个训到一半的 Llama 3 8B，在 40B token 上把学习率线性降到 0，混入 30% 的新数据集和 70% 的默认配比，看下游分数涨多少。学习率降到 0 的这一段叫退火，模型在这一段对数据最敏感，所以小剂量的好数据能被看出来。用同样的办法，他们发现在退火里加入 GSM8k 和 MATH 的训练集，8B 模型在这两个验证集上分别涨 24.0% 和 6.4%，405B 几乎没有变化。【文中有据，Llama 3 报告第 6 页】

这个结果有两种读法。报告的读法是 405B 的上下文学习能力足够强，不需要领域内样本。另一种读法是：退火对小模型的帮助很大一部分来自学会了题目的格式，大模型本来就会。后一种读法意味着，在 8B 上用退火给数据估价，会系统地高估格式类数据对旗舰模型的价值。【推断，依据：两个模型增益的差距】

OLMo 2 把这一套做成了固定的两段式：前 90% 到 95% 的算力是预训练，用以网页为主的数据；最后 5% 到 10% 叫中期训练（mid-training），学习率线性降到 0，换成上采样后的高质量网页、精选的非网页数据和专门补数学的合成数据。7B 模型的中期训练做三次，每次 50B token、数据顺序不同，最后把三个模型的权重平均。【文中有据，OLMo 2 第 6 至 7 页】

测试集污染

预训练语料来自全网，评测集也在网上。Llama 3 用 8-gram 重叠来判断一道评测题是否被污染：题目里有足够比例的 token 落在某个在训练语料中出现过的 8-gram 里，就算污染；这个比例的阈值对每个评测集分别选，选那个让干净子集和全集分数差距最大的值。结果很不均匀：HellaSwag 有 85% 的题目被判为污染，估计带来约 14.8 个点的虚高；PiQA 55%，约 8 个点；Natural Questions 也有 52% 被判为污染，但分数几乎不受影响；GSM8K 41%，影响在 0 到 1.3 个点之间。【文中有据，Llama 3 报告第 33 至 34 页、表 15】

污染的比例和它造成的虚高不是一回事。Natural Questions 的题目短、答案是常见事实，在网上出现过不代表模型背下了答案；HellaSwag 是续写题，原文出现过就等于见过标准答案。读一份评测报告时，该问的不是污染了多少，而是在干净子集上的分数是多少。

OLMo 2 报告里有一个很诚实的脚注：预训练完之后发现数学能力差，他们从 GSM8K 的 1319 道测试题里抽了 200 道当开发集来调中期训练的数据，之后只在剩下的 1119 道上报告成绩。【文中有据，OLMo 2 第 7 页脚注 6】这种做法在业界很普遍，只是很少被写出来。只要开发集和报告集严格分开，它是合理的；危险在于反复看同一份测试集来调数据，调到第十次时，这份测试集已经变成了训练信号的一部分。

数据这一步最典型的失效，是一个在小模型消融里胜出的处理，放到大模型上没有效果甚至变差。症状是旗舰模型在某类任务上的分数低于缩放律的预测。先跑的诊断是在同一份数据上补一个中间尺度（比如 7B）的点，看偏差从哪个尺度开始出现；如果小模型和中模型都符合预期，问题多半在数据的总量上：一个过滤规则在 350B token 的消融里留下的数据足够用，按同样的保留率放到 15T 的需求上，高质量部分可能要重复好几遍。补丁是降低过滤阈值或者混入更多来源，代价是平均质量下降。Muennighoff 等人的实验给过一个参考：同一份数据重复 4 个 epoch 以内，和用全新数据几乎没有差别，再往上收益快速递减。【推断，依据：FineWeb-Edu 阈值的讨论；重复数据的结论出自 Muennighoff et al. 2023】

分词器

分词器看上去是个小部件，它决定了一个 token 是什么，因此也决定了前面所有关于 token 数的预算具体指多少文字。现在的主流做法是字节级 BPE（byte-pair encoding）：从 256 个字节出发，在训练语料里反复找出现次数最多的相邻一对，合并成一个新 token，记下这条合并规则，直到词表达到目标大小。编码时按规则的先后顺序重放这些合并。

下面这个分词器就是这样训出来的，训练语料是本页的正文，最多 __BPEK__ 次合并。拖动滑块，看三行文字的切分方式怎么随合并次数变化。

图 5在本页正文上训练的字节级 BPE。上面三行是切分结果，相邻 token 用深浅两种底色区分；橙红的小块是一个汉字被切开后剩下的单个字节，显示为十六进制。下面的曲线是整份正文每个 token 平均对应的字符数，橙色点是滑块当前的位置。

滑块拖到最左边时，每个字节是一个 token：英文一个字母一个 token，汉字在 UTF-8 里占三个字节，一个汉字变成三个橙红的碎块。往右拖，最先被合并的是最常见的字节对，在这份以中文为主的语料里，最先出现的合并几乎都是把汉字的三个字节拼回一个字。再往右，常用词和词组开始成为单个 token。英文那一行的变化慢得多，因为这份语料里英文很少；代码那一行几乎不动。分词器在什么数据上训，就对什么数据压缩得好，这是这张图最直接的结论。

这个结论在大模型上有具体的代价。Llama 2 的词表是 32K，Llama 3 换成了 128K：其中 100K 来自 OpenAI 的 tiktoken，另加 28K 专门给非英语语言的 token。在一份英文样本上，平均每个 token 对应的字符数从 3.17 升到 3.94。报告的说法是，同样的训练算力能读更多的文字；加的 28K 非英语 token 改善了压缩率和下游表现，对英文的切分没有影响。【文中有据，Llama 3 报告第 7 页】按字符算，3.94 比 3.17 多 24%，同样 15T token 的预算，相当于多读了 24% 的文本。

大词表的代价在嵌入层上，可以手算。Llama 3 8B 的实际词表是 128,256（表 3 写的 128,000 是约数，多出的 256 个是特殊 token），宽度 4096，输入嵌入是 $128256\times4096=5.25$ 亿个参数，输出层不和它共享，又是 5.25 亿。合计 10.5 亿，占 8.03B 的 13%。同样的词表放到 405B 上只占 1%。所以词表大小对小模型是一个昂贵的决定，对大模型几乎免费。OLMo 2 在 1B 模型、100B token 上对比了新旧两种分词器，新的略好，同时说明在这个规模上大词表其实处于略微不利的位置，预期收益在更大的模型上才会显出来。【文中有据，OLMo 2 第 6 页、表 2】

分词器还有一个容易被忽略的后果：不同分词器下的 token 数不能直接比。DeepSeek-V3 的 14.8T 是在它自己 128K 词表下的计数（报告第 22 页明确写了 in our tokenizer），FineWeb 的 15T 是 GPT-2 分词器下的计数，Llama 3 的 15.6T 又是另一套。跨报告比较数据量时，换算成字节或字符才有意义。

分词器第一版最常见的问题出在数字和空白上。按普通 BPE 训，常见的年份和整数会被合成一个 token，而罕见的数字被切得七零八落，模型做算术时看到的是一堆不规则的块。现在的做法是在预切分阶段就把连续数字按每 1 到 3 位切开（本页的分词器也是这样做的），保证同一个数字不论出现频率高低都按同样的方式切。另一个问题是代码里的缩进：连续空格如果不单独处理，会和后面的关键字合成成千上万种组合，白白占用词表。诊断很便宜，拿一份代码和一份带数字的文本，打印切分结果看一眼就够；代价是这些预切分规则要在训练分词器之前就定下来，之后改就要重训整个模型。
